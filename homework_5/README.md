# Data Warehouse — поездки на электросамокатах

## Бизнес-процесс

В рамках данной модели рассматривается бизнес-процесс **совершения поездок на электросамокатах**.

Процесс описывает использование электросамокатов пользователями: пользователь начинает поездку в определённой локации, использует конкретный самокат и завершает поездку в другой локации.

Хранилище данных содержит информацию о поездках, которая используется для последующего анализа использования самокатов и выручки.

## Модель Data Warehouse

Для моделирования используется **звёздная схема (Star Schema)**, состоящая из одной таблицы фактов и четырёх таблиц измерений.

### Таблица фактов

**fact_rides** — центральная таблица фактов.

Она хранит информацию об отдельных поездках на самокатах:

- дату поездки;
- пользователя;
- самокат;
- начальную локацию;
- конечную локацию;
- продолжительность поездки;
- расстояние;
- стоимость поездки.

**Grain таблицы `fact_rides` — одна строка соответствует одной поездке на электросамокате.**

### Таблицы измерений

#### dim_date

Содержит информацию о дате поездки.

Позволяет анализировать количество поездок и выручку в разрезе дат.

#### dim_user

Содержит информацию о пользователях.

Позволяет анализировать активность пользователей и связанные с ними поездки.

#### dim_scooter

Содержит информацию о самокатах и их моделях.

Позволяет анализировать использование самокатов и популярность различных моделей.

#### dim_location

Содержит информацию о локациях.

Позволяет анализировать места начала и окончания поездок.

## Почему выбраны именно эти измерения

Выбранные измерения отражают основные аналитические характеристики бизнес-процесса поездок:

- **Дата** — когда была совершена поездка;
- **Пользователь** — кто совершил поездку;
- **Самокат** — какой самокат использовался;
- **Локация** — где поездка началась и где закончилась.

Таблица `fact_rides` связывает эти измерения и содержит количественные показатели, которые можно использовать для анализа, например продолжительность, расстояние и стоимость поездки.

## Структура схемы

Модель построена по принципу **звёздной схемы**:

- `fact_rides` является центральной таблицей фактов;
- `dim_date`, `dim_user`, `dim_scooter` и `dim_location` являются таблицами измерений;
- таблица `fact_rides` содержит внешние ключи, связывающие каждую поездку с соответствующими измерениями.
